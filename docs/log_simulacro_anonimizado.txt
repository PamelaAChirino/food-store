Limitación observada (ver informe_incidente.md, punto 5): todas las
sentencias -- incluidas las ejecutadas "como" app_web mediante SET ROLE --
quedan registradas bajo el usuario de conexión real (aquí anonimizado como
USUARIO_SISTEMA), no bajo app_web. El log nativo de PostgreSQL identifica el
rol de SESIÓN, no el rol EFECTIVO tras un SET ROLE. En un despliegue real,
app_web se conectaría directamente con sus propias credenciales (sin pasar
por SET ROLE desde una cuenta administrativa), y esta ambigüedad no
existiría.
